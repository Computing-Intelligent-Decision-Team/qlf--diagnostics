# Magic Extraction And Netgen LVS Trial

## Current Goal

Run a first automated Magic extraction and Netgen LVS trial on the Sky130-remapped
inverter GDS. This checks whether Magic can extract a SPICE netlist from the
remapped GDS and whether Netgen can compare it against an LVS-friendly source
netlist.

Depending on the local installation, the LVS executable may be named `netgen`
or `netgen-lvs`. The wrapper checks for `netgen` first and falls back to
`netgen-lvs`.

LVS is not required to pass at this stage. The main goal is to produce clear
logs and expose the next compatibility issues.

The current wrapper performs connectivity LVS. It intentionally normalizes the
source and extracted netlists to avoid property-only mismatches while the
Sky130 adapter is still being brought up.

## Run Command

From the MAGICAL repository root:

```bash
tools/sky130_adapter/run_magic_lvs_inverter.sh
```

If a different Sky130A PDK root is needed:

```bash
SKY130A=/path/to/sky130A tools/sky130_adapter/run_magic_lvs_inverter.sh
```

## Success Criteria

- `magic` starts and loads `sky130A.magicrc`.
- Magic reads `examples/inverter_sky130_try/inverter_core.sky130.gds`.
- Magic loads `inverter_core_flat`.
- Magic runs `extract all`.
- Magic runs `ext2spice lvs`, `ext2spice cthresh 0`, `ext2spice rthresh 0`,
  and `ext2spice`.
- `generated/sky130_lvs/inverter_core_extracted.spice` is produced.
- `generated/sky130_lvs/inverter_core_extracted_normalized.spice` is produced.
- `generated/sky130_lvs/inverter_source_for_lvs.spice` is produced.
- If `netgen` or `netgen-lvs` is available, Netgen runs and writes
  `netgen_lvs.log` and `netgen_lvs_report.out`.

LVS passes only if the Netgen report says the circuits match. A nonzero Netgen
exit code or mismatch report is useful diagnostic output, not a failure of this
automation step.

## Common Failure Causes

- Cell name mismatch between `inverter_core` and `inverter_core_flat`.
- Pin name or pin order mismatch.
- Device model name mismatch between source and extracted netlists.
- Magic reads the GDS but extracts no MOS devices.
- The layer remap is sufficient for DRC loading but not sufficient for correct
  extraction connectivity.
- Neither `netgen` nor `netgen-lvs` is installed or present in `PATH`.

## Current Normalization

The wrapper currently runs
`tools/sky130_adapter/normalize_lvs_netlists_inverter.py` after Magic extraction.
This is an inverter-specific temporary normalization step:

- It removes extracted parasitic capacitor lines.
- It renames known Magic-generated nets back to `A`, `Y`, `VPWR`, and `VGND`.
- It changes `.subckt inverter_core_flat` to
  `.subckt inverter_core_flat A Y VPWR VGND`.
- It removes `ad/as/pd/ps` layout-derived MOS properties from the extracted
  netlist to avoid property-only mismatches in this connectivity LVS trial.
- It keeps `w/l`.

This is not a general LVS solution. The long-term fix should preserve or create
correct GDS labels/pins so Magic extraction keeps the intended port names
without hard-coded inverter net renaming.

PEX-oriented flows should not discard parasitic capacitors or layout-derived
properties such as `ad/as/pd/ps`; those are only stripped here for the current
connectivity LVS experiment.

## Current Limits

- The layout is generated by MAGICAL and then layer/datatype-remapped.
- Passing Magic DRC does not imply LVS will pass.
- Sky130 extraction behavior still needs review for contacts, local
  interconnect, well/tap, implant, and device recognition.
